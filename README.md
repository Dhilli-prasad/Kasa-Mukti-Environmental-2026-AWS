# KasaMukti

KasaMukti turns waste from an end-of-life problem into a recoverable resource. The hackathon MVP connects citizen collection, AI identification, safe hazard handling, human verification, GreenPoints, municipal inventory, recovery matching, and impact analytics.

## Run the frontend

```powershell
Set-Location .\frontend
npm install
Copy-Item .env.example .env
# Set VITE_API_BASE_URL to the deployed HttpApi URL
npm run dev
```

The frontend uses live `fetch` requests only. It displays AWS network/loading/error states and does not seed demo records.

### Hackathon presentation mode

For a repeatable three-minute presentation, set `VITE_DEMO_MODE=true`. This activates
an explicitly labelled, local-only journey controller with seeded citizen, worker,
municipal, matching, and impact records. It never silently masquerades as AWS data:
the header says `SIMULATED DEMO`, the network badge says `Demo simulation`, and the
scanner labels its result as simulated. Set it back to `false` for live API calls.

```powershell
Copy-Item .env.example .env
# Set VITE_DEMO_MODE=true for the presentation
npm run dev
```

For a deployed AWS-only presentation table, seed the fixed demonstration records
into a dedicated DynamoDB table:

```powershell
$env:TABLE_NAME="KasaMuktiDemo"
python .\backend\seed_demo.py
```

The seed is additive and never clears a table. Use a dedicated hackathon table;
do not run it against production data.

### Three-minute presenter runbook

1. Start on the citizen overview and introduce the Ward 12 pesticide-container story.
2. Click **Next moment** to open the scanner and show the simulated image plus
   `CRITICAL` risk, verified warning, and `SPECIALIZED TREATMENT` pathway.
3. Advance through the collection-center and deposit moments, then switch to the
   worker view to show physical verification and the 1.2 kg trust gate.
4. Advance to **GreenPoints unlock** to show 120 points and the first-return badge.
5. Advance through **Material enters the bank** and **Create recovery batch** to
   show `KM-BATCH-042`, quality status, and safe hazardous routing.
6. Open **Ask AI Copilot** and finish on **Show impact** for the city-level
   diversion and verified-deposit metrics.

The progress rail is clickable, so the presenter can jump to a moment if a live
audience asks a question. The demo intentionally never claims that simulated
steps wrote to AWS.

## Deploy the backend

```powershell
sam build --template-file template.yaml
sam deploy --guided --template-file .aws-sam\build\template.yaml
```

The deployment creates the HTTP API, DynamoDB table, private encrypted S3 bucket, SNS hazard topic, Cognito user pool, and Lambda. Bedrock model access must be enabled in the target AWS region.

For a judge-only environment where Cognito is not yet configured, explicitly opt into the temporary demo identity headers:

```powershell
sam deploy --guided --template-file .aws-sam\build\template.yaml --parameter-overrides AllowDemoIdentity=true
```

Keep `AllowDemoIdentity=false` for production. The demo header path is not authentication.

## Roles

The product roles are `CITIZEN`, `FARMER`, `MUNICIPAL_WORKER`, `MUNICIPAL_OFFICER`, `RECOVERY_PARTNER`, and `ADMIN`. Production API calls should carry Cognito JWT claims. A temporary demo identity header is available only when `ALLOW_DEMO_IDENTITY=true` and is intentionally documented as non-production.
Live mode uses the Cognito User Pool and public app-client values (`VITE_COGNITO_USER_POOL_ID` and `VITE_COGNITO_CLIENT_ID`) for sign-in, session restoration, logout, and JWT forwarding. The legacy `VITE_COGNITO_ID_TOKEN` is retained only for controlled compatibility testing.

## Safety and rewards

Image analysis creates a `PENDING` scan and awards zero points. Points are granted only after a municipal worker verifies a physical deposit. Hazardous guidance is selected from a verified backend registry, not generated by the model. Critical alerts are published to SNS and cannot be routed to public upcycling.

See [ARCHITECTURE.md](./ARCHITECTURE.md) for the entity model, trust boundaries, AWS services, and phased implementation plan.

## AI assistant

The assistant uses `POST /chat` with role context, a conversation ID, optional
base64 image context, live DynamoDB-backed context, and source metadata in the
response. Verified hazard guidance is loaded from
`backend/knowledge/guidance.py`; Bedrock is never allowed to author hazardous
instructions. Set `BEDROCK_DISABLED=true` in a local Lambda environment to use
the safe local provider while developing the API boundary without AWS calls.

## Waste Intelligence

`POST /analyze` returns a normalized `WasteAnalysis` with `category`,
`materialType`, `manufacturer`, `productName`, `hazardLevel` (`LOW`, `MEDIUM`,
`HIGH`, `CRITICAL`), `confidence`, `recommendedPathway`,
`requiresManualVerification`, and `explanation`. Unknown or low-confidence
results are capped at 59% confidence and require human review. High and
critical hazards always require municipal verification; hazardous guidance is
selected from the versioned verified knowledge module rather than generated by
the model.

The deterministic risk assessment is returned under `riskAssessment` and is
also persisted with each pending scan. It uses configurable verified rules for
pesticide/agricultural chemicals, batteries, e-waste, chemical containers,
medical/sharps waste, contamination, and unknown hazardous objects. A matched
rule overrides a benign model material label, blocks prohibited recovery
pathways, and cannot emit instructions to burn, open, wash, or reuse an item.

The provider is selected with `WASTE_CLASSIFIER_PROVIDER=bedrock` (the
production default). `mock` is available only for local contract tests and
returns an explicit unknown, zero-confidence result. The provider protocol in
`backend/ai/waste_intelligence.py` leaves room for an AWS computer-vision or
custom ML implementation without changing the API contract.

## GreenPoints

GreenPoints are awarded only by verified environmental actions. A scan or image
upload creates no reward transaction. Municipal workers, officers, and admins
can verify deposits through `/verify` or `/collection-events`; the backend then
creates an idempotent `GREENPOINT_TRANSACTION` and updates the user's wallet.
Supported actions include recyclable deposits, special-waste deposits,
agricultural-container returns, collection events, illegal-dumping reports,
and approved campaigns. Reward values are configured with
`GREENPOINT_REWARD_RULES_JSON` and fall back to the reviewed defaults.
Duplicate image hashes, event idempotency keys, scan status conditions, and
transaction reference keys prevent repeated rewards.

## Municipal Material Bank

Municipal workers create batches only from verified deposits through
`POST /batches` and manage them with `PATCH /batches/{batchId}`. Each batch
stores material type, quantity, verified weight, source collection centers,
risk status, quality and contamination status, creation metadata, eligible
recovery pathways, and one of the controlled statuses:
`COLLECTING`, `AGGREGATING`, `QUALITY_CHECK`, `READY_FOR_RECOVERY`,
`PARTNER_REQUESTED`, `PICKUP_SCHEDULED`, `RECOVERED`, or `REJECTED`.
Recovery routing requires a passed or acceptable quality status.

## Recovery Matching

`GET /matches` uses the deterministic engine in
`backend/recovery_matching.py`. It ranks eligible verified partners by the
configured pathway priority: safe reuse, recycling, producer recovery,
upcycling, community projects, then specialized treatment. It checks material,
hazard, quality, contamination, quantity, verification, geographic service
radius, and distance. Hazardous batches cannot route to ordinary producers,
reuse partners, upcyclers, or community projects. Results include a reason,
distance, priority, and pathway; AI is not used for eligibility decisions.

## Public Upcycling

Municipal officers can create `CircularProject` records through `POST /projects`.
Projects contain `MaterialRequirement` entries, estimated quantities, approval
state, project status, community participants, and `ProjectImpact` metrics.
Approval is mandatory before material allocation; allocation checks every actual
batch with the deterministic public-installation safety gate. Hazardous,
prohibited, quality-pending, or contaminated material is rejected and cannot be
automatically selected for park art, sculptures, planters, educational
installations, furniture, or other public projects.

Project status changes use `PATCH /projects/{projectId}`. Completed projects
retain a QR token and can be viewed without authentication at
`GET /public-projects/{qrToken}`, showing the project description, materials,
amount diverted, and participating community.
